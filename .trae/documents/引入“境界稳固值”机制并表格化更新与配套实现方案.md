# 改造方案概述

## 数据库存储（按你要求写入 users 表）
- users 表新增字段：
  - `realm_name TEXT`（当前境界名称，如“筑基初期”）
  - `realm_stability INTEGER DEFAULT 0`（境界稳固值百分比 0–100）
- system_config 增加键：
  - `realm_tiers`：各等级标准修为与上一巅峰修为（JSON，来源于《数据资料.md》现有表数据）
  - `stability_gain_config`：修炼、闭关、丹药、任务的稳固值增减参数（JSON）
- 迁移策略：初始化时检测并添加缺失列，保证兼容既有数据（不破坏已有逻辑）。

## 核心联动逻辑（修为/稳固值变化即判断境界变化）
- API 扩展（`core/api/game.py`）：
  - `get_realm_rules() -> dict`（读取 `system_config.realm_tiers`）
  - `get_current_realm_by_xp(xp) -> str`（按 JSON 规则计算当前境界）
  - `get_user_realm_state(user_id) -> {realm_name, realm_stability}`
  - `set_user_realm_state(user_id, realm_name=None, stability=None)`
  - `add_stability(user_id, amount_percent)`（正增负减，限幅 0–100）
  - `check_and_update_realm(user_id, new_xp=None, new_stability=None)`：
    - 读取规则，计算分区（稳固/危险/跌落）
    - 当 XP 下降进入危险区：稳固值>0 → 保持境界；稳固值=0 → 继续损失则跌落为上一大境界巅峰
    - 当 XP≤上一巅峰：无论稳固值多少 → 直接跌落
    - 当 XP≥标准修为：更新为该境界并视为稳固区
- 调用点：
  - 在 `add_xp` 完成后调用 `check_and_update_realm(user_id, new_xp)`（尤其负数场景）
  - 在 `add_stability` 完成后也调用（稳固值变化可能影响危险/稳固区判定）

## 事件系统支持
- 条件：
  - `stability_gte`（稳固值≥）
  - `stability_range`（稳固值范围）
- 效果：
  - `add_stability` / `remove_stability`（按百分比增减）
  - `realm_drop_to_previous_peak`（直接跌落到上一巅峰并设置 XP）
- 模板事件：
  - “突破后巩固”：定时或命令触发 → 增加稳固值（丹药/闭关/任务）
  - “重伤失稳”：战斗失败 → 扣减稳固值 + 调用跌落判定

## 物品与效果（结合凡人修仙传）
- 新物品（通过后台 Items 创建）：
  - 固元丹（稀有度 `rare`）：`stability +15%`，冷却 12h
  - 凝神丹（`uncommon`/`common`）：`stability +8%`，冷却 6h
  - 天心丹（`epic`）：`stability +25%`，仅突破后 72h 可用
  - 护道符（`common`）：危险区内一次性避免跌落（消耗后稳定值+5%）
- 效果实现：
  - 在 `core/event_system/effects/attribute_effect.py` 中新增 `AddStabilityEffect`/`RemoveStabilityEffect`
  - 通过 `generic_api` 可直接调用 `add_stability` 或 `check_and_update_realm`

## 后台管理（API 与前端）
- 新路由：
  - `GET/PUT /api/realm/state/{user_id}`（查询/更新用户境界与稳固值）
  - `GET/PUT /api/realm/rules`（读取/更新 `realm_tiers` 与分区参数）
