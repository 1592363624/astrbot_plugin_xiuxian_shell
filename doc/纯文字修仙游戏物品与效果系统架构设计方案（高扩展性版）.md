# 纯文字修仙游戏物品与效果系统架构设计方案（高扩展性版）

# 一、架构设计核心原则

本架构以「高扩展性」为核心，兼顾纯文字交互的简洁性，同时满足「物品无限堆叠、无重量、无品质区分」的核心要求，重点解决物品使用时的条件判断、提示反馈、效果扩展三大问题，确保后续新增物品类型、效果类型、使用规则时，无需大幅修改核心代码，仅需通过配置扩展即可实现。

核心原则拆解：

- 高扩展性：采用「核心逻辑\+配置化扩展」模式，物品、效果、使用条件均通过配置文件定义，脱离代码硬编码；

- 无重量/无品质：物品属性中剔除重量、品质相关字段，仅保留核心功能相关属性；

- 无限堆叠：通过堆叠标识统一管理，同类型物品默认无限堆叠，仅记录数量；

- 灵活提示：封装统一的提示生成逻辑，覆盖「条件不满足、缺少物品、数量不足」等所有场景，提示文案可配置，适配纯文字展示。

# 二、整体架构分层（从上到下，依赖递减）

架构分为4层，各层独立解耦，下层为上层提供支撑，扩展时仅需修改对应层的配置或新增实现类，不影响其他层逻辑：

1. 交互提示层：负责物品使用、获取、消耗等所有场景的文字提示生成与展示，承接上层逻辑的反馈，面向玩家输出清晰信息；

2. 核心业务层：负责物品的使用、消耗、效果触发、条件校验等核心逻辑，是架构的核心枢纽；

3. 配置定义层：负责物品、效果、使用条件、提示文案的配置化定义，所有可扩展内容均在此层维护；

4. 基础支撑层：负责数据存储、配置加载、工具类封装（如数量校验、条件匹配），为上层提供基础服务。

# 三、各层详细设计

## （一）基础支撑层

核心作用：提供通用支撑能力，确保上层逻辑可复用、可扩展，减少重复开发，同时保障数据稳定性。

### 1\. 数据存储模块

负责存储玩家物品数据、全局物品配置、效果配置等，采用「键值对\+配置文件」结合的方式，适配纯文字游戏的轻量化需求：

- 玩家物品数据：存储格式为「物品ID: 数量」，无需存储重量、品质，仅记录核心信息，示例：\{\&\#34;item\_001\&\#34;: 999, \&\#34;item\_002\&\#34;: 15\}；

- 全局配置存储：所有物品、效果、提示文案均以JSON/YAML配置文件存储，加载时缓存至内存，修改配置后重启服务即可生效，无需重新编译代码；

- 扩展点：支持新增存储字段（如物品关联任务ID），无需修改存储核心逻辑，仅需扩展配置文件字段即可。

### 2\. 工具类模块

封装通用工具方法，供上层调用，降低耦合：

- 数量校验工具：校验物品数量是否满足使用需求，返回校验结果（满足/不满足\+缺少数值）；

- 条件匹配工具：校验玩家当前状态（境界、修为、任务进度等）是否满足物品使用条件，返回不满足的具体原因；

- 配置加载工具：统一加载各类配置文件，支持热更新（可选），新增配置后无需重启服务即可生效；

- 扩展点：新增校验规则（如新增「门派限制」校验）时，仅需新增工具方法，无需修改上层业务逻辑。

## （二）配置定义层

核心作用：所有可扩展内容均在此层定义，是实现高扩展性的核心，后续新增物品、效果、提示，仅需修改或新增配置，无需改动核心代码。

### 1\. 物品配置（核心配置）

采用统一配置模板，所有物品共用同一模板，无品质、重量字段，重点定义「使用逻辑、关联效果、堆叠规则」，示例配置（JSON格式）：

```json
{
  "item_config": [
    {
      "item_id": "item_001",          // 物品唯一ID（不可重复，用于区分物品）
      "item_name": "聚气丹",          // 物品显示名称（纯文字）
      "item_desc": "普通聚气丹药，可提升少量修为", // 物品描述（纯文字）
      "stackable": true,              // 堆叠标识（固定为true，所有物品均支持无限堆叠）
      "use_type": "active",           // 使用类型：active（主动使用）/ passive（被动触发，如佩戴）
      "use_conditions": [             // 使用条件（可空，无条件则无需配置）
        {
          "condition_type": "realm",  // 条件类型：realm（境界）/ cultivation（修为）/ item（所需物品）
          "condition_value": "qi_refining_1", // 条件值：境界为炼气一层
          "prompt_key": "realm_not_enough" // 不满足条件时的提示文案key，关联提示配置
        },
        {
          "condition_type": "item",
          "condition_value": "item_003", // 所需物品ID
          "condition_num": 1,          // 所需物品数量
          "prompt_key": "lack_item"
        }
      ],
      "consume_num": 1,               // 使用时消耗的本物品数量（可配置，如一次性使用3颗）
      "effect_ids": ["effect_001"],   // 关联的效果ID（可多个，按顺序触发）
      "prompt_key_success": "use_success_juju_dan" // 使用成功提示文案key
    }
  ]
}
```

配置说明：

- item\_id：唯一标识，新增物品时仅需新增一条配置，分配唯一ID即可；

- stackable：固定为true，所有物品默认无限堆叠，无需额外处理堆叠上限；

- use\_conditions：支持多条件组合（逻辑与），可新增条件类型（如「门派限制」「任务进度」），仅需扩展condition\_type字段及对应校验逻辑；

- effect\_ids：关联效果，新增效果时仅需新增效果配置，再在此处关联即可，无需修改物品使用逻辑。

### 2\. 效果配置

采用「效果类型\+参数配置」模式，支持多种效果类型，新增效果时仅需新增配置，无需修改触发逻辑，示例配置：

```json
{
  "effect_config": [
    {
      "effect_id": "effect_001",      // 效果唯一ID
      "effect_name": "聚气效果",      // 效果名称（用于日志/提示）
      "effect_type": "add_cultivation", // 效果类型：add_cultivation（增加修为）/ add_attribute（增加属性）/ trigger_task（触发任务）
      "effect_params": {              // 效果参数（根据效果类型动态配置）
        "cultivation_value": 100,     // 增加的修为值
        "duration": 0                 // 持续时间（0表示立即生效，无持续时间）
      },
      "effect_desc": "使用后获得100点修为" // 效果描述（用于物品描述/使用提示）
    },
    {
      "effect_id": "effect_002",
      "effect_name": "防御加成",
      "effect_type": "add_attribute",
      "effect_params": {
        "attribute_type": "defense",
        "attribute_value": 50,
        "duration": 3600              // 持续1小时（单位：秒）
      },
      "effect_desc": "1小时内防御+50"
    }
  ]
}
```

扩展点：新增效果类型（如「境界突破概率提升」「解除debuff」）时，仅需新增effect\_type，同时在核心业务层新增对应效果触发实现类，无需修改其他效果的逻辑。

### 3\. 提示文案配置

统一管理所有提示文案，支持动态替换参数（如缺少数值、当前境界），避免硬编码，方便后续修改文案风格，示例配置：

```json
{
  "prompt_config": {
    "realm_not_enough": "境界不足，无法使用【{item_name}】，需达到{condition_value}（当前：{current_realm}）",
    "lack_item": "缺少使用【{item_name}】所需物品：【{lack_item_name}】x{lack_num}（当前拥有：{current_num}）",
    "lack_num": "【{item_name}】数量不足，需{need_num}个（当前拥有：{current_num}）",
    "use_success_juju_dan": "成功使用【聚气丹】，获得{cultivation_value}点修为！",
    "use_passive": "【{item_name}】被动生效，{effect_desc}",
    "no_use_permission": "无法使用【{item_name}】，无使用权限"
  }
}
```

配置说明：文案中的\{xxx\}为动态参数，由交互提示层根据实际场景替换，无需修改文案配置，仅需在提示生成时传入对应参数即可。

## （三）核心业务层

核心作用：承接配置层的定义，实现物品使用、效果触发、条件校验等核心逻辑，是架构的核心枢纽，所有业务逻辑均在此层封装，确保可扩展、可复用。

### 1\. 物品管理模块

负责玩家物品的增、删、改、查，以及堆叠逻辑的处理，核心方法：

- 物品获取（addItem）：根据物品ID，直接增加对应数量（无限堆叠，无需判断上限），若物品不存在则新增记录；

- 物品消耗（consumeItem）：根据物品ID和所需数量，校验数量是否充足，充足则扣除对应数量，不足则返回数量不足提示；

- 物品查询（getItemInfo）：根据物品ID，查询物品名称、描述、数量、使用条件等信息，供交互层展示；

- 堆叠逻辑：无需额外处理，仅通过「物品ID\+数量」存储，同ID物品自动堆叠，展示时仅需显示「物品名称x数量」（如「聚气丹x999」）。

扩展点：新增物品操作（如物品交易、物品丢弃）时，仅需新增对应方法，无需修改现有逻辑。

### 2\. 条件校验模块

负责校验物品使用时的所有条件，调用基础支撑层的工具类，返回校验结果（成功/失败\+提示信息），核心逻辑：

1. 接收物品使用请求（玩家ID、物品ID、使用数量）；

2. 查询该物品的使用条件配置（use\_conditions）；

3. 逐一对条件进行校验（境界、修为、所需物品等）；

4. 若所有条件满足，返回校验成功；若任意条件不满足，根据配置的prompt\_key，从提示文案配置中获取对应文案，替换动态参数后返回校验失败及提示信息。

扩展点：新增条件类型（如「门派限制」）时，仅需在本模块新增对应条件的校验方法，同时在配置层扩展condition\_type字段，无需修改其他条件的校验逻辑。

### 3\. 效果触发模块

负责根据物品关联的效果ID，触发对应效果，核心逻辑：

1. 条件校验通过后，调用物品管理模块消耗对应数量的物品；

2. 查询该物品关联的所有效果ID（effect\_ids）；

3. 逐一对效果进行触发：根据效果类型（effect\_type），调用对应效果的实现类，传入效果参数（effect\_params）和玩家ID；

4. 触发完成后，返回效果触发结果，供交互提示层生成成功提示。

扩展设计：采用「接口\+实现类」模式，定义统一的效果接口（IEffect），所有效果类型均实现该接口，新增效果时仅需新增实现类，无需修改触发核心逻辑，示例：

- 接口：IEffect，包含方法trigger\(Player player, Map\&lt;String, Object\&gt; params\)；

- 实现类：AddCultivationEffect（增加修为）、AddAttributeEffect（增加属性）；

- 触发时，根据effect\_type，通过反射获取对应实现类，调用trigger方法，实现效果触发。

## （四）交互提示层

核心作用：面向玩家，生成简洁、清晰的纯文字提示，承接核心业务层的反馈，确保玩家能明确了解物品使用的结果、条件不足的原因等，核心逻辑：

1. 接收核心业务层的反馈（校验结果、效果触发结果）；

2. 根据反馈类型（成功、失败、条件不足等），获取对应的提示文案（从提示文案配置中）；

3. 替换文案中的动态参数（如物品名称、缺少数值、当前境界等）；

4. 以纯文字形式展示给玩家，确保提示简洁、直观，符合修仙游戏的风格。

常见提示场景及示例：

- 数量不足：「【聚气丹】数量不足，需1个（当前拥有：0）」；

- 境界不足：「境界不足，无法使用【聚气丹】，需达到炼气一层（当前：炼气初期）」；

- 缺少所需物品：「缺少使用【聚气丹】所需物品：【丹炉】x1（当前拥有：0）」；

- 使用成功：「成功使用【聚气丹】，获得100点修为！」；

- 被动效果触发：「【防御玉佩】被动生效，1小时内防御\+50」。

扩展点：新增提示场景（如物品过期、使用冷却）时，仅需在提示文案配置中新增对应文案，在核心业务层新增对应反馈逻辑，无需修改提示生成核心逻辑。

# 四、高扩展性设计细节

## 1\. 配置与代码解耦

所有物品、效果、提示文案均通过配置文件定义，核心代码仅负责解析配置、执行逻辑，新增物品/效果时，无需修改代码，仅需新增配置，降低开发成本，同时支持快速迭代。

## 2\. 接口化与模块化

核心业务层的效果触发、条件校验均采用接口化设计，新增功能时仅需实现接口、新增模块，无需修改现有代码，避免代码冗余，同时提高代码可维护性。

## 3\. 动态参数支持

提示文案、效果参数均支持动态替换，无需硬编码数值或文案，后续修改数值（如聚气丹修为加成从100改为150）、调整提示文案，仅需修改配置文件，无需重启服务（可选热更新）。

## 4\. 无限扩展的条件与效果类型

条件类型（condition\_type）、效果类型（effect\_type）均支持无限扩展，新增类型时，仅需：

- 在配置文件中新增对应类型的配置；

- 在核心业务层新增对应的校验/实现类；

- 无需修改其他层的核心逻辑，实现无缝扩展。

# 五、系统流程示例（物品使用全流程）

1. 玩家输入指令：「使用聚气丹x1」；

2. 交互提示层接收指令，传递给核心业务层的物品管理模块；

3. 物品管理模块查询玩家当前「聚气丹」数量，调用数量校验工具，确认数量是否充足（若不足，返回数量不足提示，交互层展示）；

4. 数量充足后，条件校验模块查询「聚气丹」的使用条件，逐一对条件进行校验（如境界是否达标、是否有所需物品）；

5. 条件校验通过，物品管理模块消耗1个「聚气丹」；

6. 效果触发模块查询「聚气丹」关联的效果ID（effect\_001），调用AddCultivationEffect类，为玩家增加100点修为；

7. 效果触发完成，核心业务层返回成功反馈，交互提示层获取对应提示文案，替换参数后展示：「成功使用【聚气丹】，获得100点修为！」。

# 六、后续扩展建议

- 新增物品类型：如「功法书」「符箓」「法宝」，仅需新增物品配置，关联对应效果（如功法书触发「学习功法」效果）；

- 新增效果类型：如「境界突破概率提升」「debuff解除」「临时传送」，仅需新增效果配置和对应实现类；

- 新增使用条件：如「门派限制」「修为上限限制」「时间限制」，仅需新增条件类型和校验方法；

- 优化提示逻辑：可新增「提示风格配置」，支持不同修仙风格的提示文案（如古风、简洁风），仅需修改提示文案配置即可。

# 七、注意事项

- 物品ID需保证唯一，新增物品时需统一规划ID规则（如item\_xxx），避免冲突；

- 效果触发逻辑需保证线程安全，避免多线程操作时出现修为、属性计算错误；

- 配置文件需定期备份，修改配置后建议先测试，避免配置错误导致系统异常；

- 提示文案需简洁明了，避免过于冗长，符合纯文字游戏的交互特点，同时确保玩家能快速理解提示含义。
