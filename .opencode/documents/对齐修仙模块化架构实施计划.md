* 已具备事件系统（触发器/条件/效果/引擎/后台CRUD）与基础数据层，模块化清晰，主入口仅注册命令，符合“主文件不写业务”的规范。

* 角色核心覆盖：用户/背包/灵石/修为/灵根/稳固值，见 core/api/game.py:33、127、167、319、200。

* 规则引擎覆盖：概率/资源/等级/稳固值，多数以条件+效果实现，见 core/event\_system/conditions/*.py 与 effects/*.py；闭关修炼收益为示例（retreat\_effect.py）。

* 缺口：技能/战斗/任务运行态/Pub-Sub总线/定时精确调度/External Comments SQL/配置一致性（realm\_levels）以及境界联动函数错位。

  * 数据访问接口：SQLite+WAL，视图与索引完善，但未实现 External Comments SQL 注释扩展（core/database/schema.sql）。

## **核心规则**

* **易维护**：判断规则集中在配置文件和规则引擎，无需在业务代码中散落。

* **高扩展**：只需加配置 + 扩展规则引擎方法，不影响现有逻辑。

* **好调试**：所有判断逻辑统一入口，问题可快速定位到规则引擎或配置文件。

* **1.数据驱动：用配置文件定义规则（无需硬编码）**

  将所有判断条件、数值阈值存入配置数据表，修改时直接改配置，无需动代码。

* **2. 规则引擎：抽象判断逻辑（统一调用接口）**

  用 Python 类封装所有判断方法，接收 “角色数据” 和 “规则配置”，返回布尔结果 + 提示信息，所有业务模块统一调用该引擎。

* **3.业务逻辑调用：解耦判断与执行**

  游戏核心流程（突破、学功法、战斗）只需调用规则引擎的判断方法，无需关心内部逻辑，新增功能时只需扩展规则引擎方法和配置文件。

* **4. 扩展判断场景：战斗胜负、奇遇触发**

  只需在规则引擎中新增判断方法，配置文件中补充规则，无需修改核心流程

### **一、物品核心分类（带专属机制）**

按功能和使用逻辑拆分 6 大类，每类明确 “获取 - 使用 - 消耗 - 再生” 路径：

#### **1. 消耗类（一次性 / 限时生效）**

* **丹药**：分基础（清灵丹、聚气丹）、进阶（筑基丹、化婴丹）、特殊（洗髓丹、避毒丹）三类。
  * 机制：使用后即时生效（如加修为、清丹毒），部分高阶丹药有 “丹毒积累”（累计超过阈值触发属性衰减），需搭配排毒丹药使用。
  * 关联：丹药品质分下 / 中 / 上 / 绝品，品质越高效果越强、丹毒越低，需对应等级炼丹师 + 高品质丹炉炼制。
* **符箓**：含攻击（爆炎符）、防御（护体符）、功能（飞行符、定身符）三类，均为一次性道具。
  * 机制：使用即销毁，高阶符箓（如雷劫符）需消耗稀有材料（雷灵晶），且有使用境界限制（如渡劫期才能用天劫护符）。

#### **2. 配方类（永久解锁，可交易）**

* 包含丹方、符箓配方、炼器图谱等，核心是 “学会即永久掌握，可二次传播”。
  * 机制：学习后解锁对应物品的炼制权限，可消耗 “空白玉简” 将配方刻录成 “可交易版本”（每人限刻录 3 次，防止无限复制）。
  * 交易限制：高阶配方（如大乘丹方）刻录需消耗稀有材料（龙血玉），且交易后对方需达到对应技艺等级（如炼丹术 5 级才能学习化神丹方）。

#### **3. 装备类（耐久制，可修复 / 养成）**

* 分穿戴装备（武器、护甲、头盔）和法宝（独立技能型装备），贴合修仙战斗逻辑。
  * 基础机制：有 “当前耐久” 和 “最大耐久”，战斗、采集时消耗耐久，耐久为 0 时无法使用（但不销毁）。
  * 修复规则：
    * 普通修复：用基础材料 + 修理包修复，恢复 60%-80% 当前耐久，但最大耐久降低 2%-5%（低阶装备降幅大）。
    * 完美修复：用稀有材料（如玄铁、灵玉）+ 对应图谱修复，恢复 100% 当前耐久，最大耐久无损耗（高阶装备必备）。
  * 养成延伸：可镶嵌灵晶（加属性）、铭刻符文（解锁被动技能），但镶嵌 / 铭刻有失败概率，失败会损伤装备耐久。

#### **4. 功能道具类（非消耗，辅助玩法）**

* 含采集工具（矿镐、药铲）、生活道具（灵田水壶、炼器模具）、特殊道具（储物袋、传送阵令牌）。
  * 机制：无使用次数限制，但有 “损耗度”，长期使用后效率下降（如低阶矿镐挖矿速度变慢），需用材料升级（如矿镐 + 玄铁升级为高阶矿镐，提升采集效率和稀有材料产出率）。
  * 关联：部分功能道具需对应生活技能等级（如采矿 3 级才能使用中级矿镐）。

#### **5. 材料类（基础 / 稀有 / 限定）**

* 分基础材料（灵草、矿石、妖兽皮）、稀有材料（龙鳞、凤羽、混沌源晶）、限定材料（活动专属、世界 BOSS 掉落）。
  * 机制：基础材料可通过采集、击杀低阶妖兽获取；稀有材料需探索秘境、组队挑战高阶妖兽；限定材料仅在特定活动或时辰产出。
  * 存储：高阶材料需扩容储物袋才能存放，否则无法获取（增加储物袋养成需求）。

#### **6. 本命类（永久绑定，唯一性）**

* 含本命法宝、专属灵根、传承信物等，角色绑定后无法交易或丢弃。
  * 机制：本命法宝需集齐碎片激活，激活后提供永久属性加成，还能通过消耗材料升级解锁专属技能（如自动反击、范围控制）。
  * 成长：传承信物可通过完成宗门任务升级，提升角色修炼速度或技艺成功率（如炼丹成功率 + 10%）。

### **二、核心系统规则（平衡玩法与体验）**

#### **1. 境界关联规则**

* 物品使用限制：装备、丹药、符箓均需角色达到对应境界才能使用（如筑基期才能穿戴二阶装备，元婴期才能用化婴丹）。
* 技艺等级关联：炼制高阶物品需对应技艺等级（如炼丹术 4 级才能炼制结丹期丹药，符箓术 3 级才能画高阶定身符）。

#### **2. 交易与流通规则**

* 可交易物品：配方刻录版、基础 / 稀有材料、非绑定装备、低中阶丹药 / 符箓。
* 不可交易物品：本命类物品、已绑定装备、高阶限定材料、配方原版（防止核心配方泛滥）。
* 交易渠道：游戏内摆摊区（收取少量手续费）、宗门拍卖（高阶物品专属）、玩家面对面交易（无手续费但有诈骗风险提示）。

#### **3. 消耗与再生闭环**

* 基础消耗：日常修炼、战斗、采集会持续消耗丹药、符箓、装备耐久，驱动材料采集和炼制玩法。
* 再生途径：灵田种植灵草、矿脉挖掘矿石（定时刷新）、NPC 每日限购基础材料、活动产出稀有材料，形成 “消耗 - 采集 - 炼制 - 再消耗” 的循环。

### **四、设计优化亮点**

1. 闭环玩法：材料采集、技艺炼制、物品消耗相互驱动，让玩家有持续目标（如为修复高阶装备而组队刷稀有材料）。
2. 风险与收益平衡：装备修复有耐久损耗，但完美修复可避免；高阶配方可交易但有刻录限制，防止通货膨胀。
3. 境界同步成长：物品解锁与角色境界、技艺等级挂钩，让每个阶段都有新的追求（如渡劫期解锁天劫护符、渡劫丹）。

### **核心设计说明（适配开发需求）**

1. **属性标准化**：所有物品统一包含「ID、名称、品质、类型、所需境界」核心字段，便于 Python 代码统一解析（如通过`item_type`区分处理逻辑）。
2. **关联逻辑清晰**：技艺等级、储物袋等级、境界严格绑定，避免玩家跨阶段使用高品物品，同时驱动 “技艺升级”“储物袋扩容” 玩法。
3. **消耗与再生平衡**：基础材料无限供应（如灵草、修理包），稀有材料定时刷新（如混沌源晶），限定材料活动产出，防止通货膨胀。
4. **代码适配性**：可直接导出为 JSON 格式，通过 Python 字典读取调用，示例如下：

```
# 读取物品配置（JSON文件）
import json

with open("item_config.json", "r", encoding="utf-8") as f:
    item_config = json.load(f)

# 示例：根据物品ID获取炼制要求
def get_craft_require(item_id):
    item = item_config.get(item_id)
    if not item:
        return "物品不存在"
    if item["type"] in ["丹药", "符箓", "装备"]:
        return item.get("craft_require", "无法炼制")
    return "非炼制类物品"

print(get_craft_require("dan_005"))  # 输出中品筑基丹的炼制要求

```
