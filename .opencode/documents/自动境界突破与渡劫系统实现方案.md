**核心变化**

* 所有境界统一在 `system_config.realm_tiers` 中配置突破规则；每一层都支持“材料、命令、概率、成功/失败事件”等，不再只为个别层级写死示例。

* 轮询与触发统一走事件系统的定时机制：不再独立 `_start_realm_auto_checker`。使用一个全局轻量轮询频率（如 1 秒），每个事件用自己的 `cooldown` 字段表达独立间隔（如 3 秒、5 分钟等）；从而满足“以后还会有不同时间间隔、不同事件判断”的需求。

**配置结构（每一层）**

* `system_config.realm_tiers`（JSON 数组，已有境界名为主）：

  * `name`: 境界名（沿用现有命名）

  * `standard_xp`: 达到该境界的标准修为

  * `prev_peak_xp`: 上一境界圆满修为

  * `breakthrough`: {

    * `requires_items`: \[{`item_name`,`quantity`}]  // 所需法宝（每层都可单独配置）

    * `command`: "冲击筑基" | "冲击结丹" | "冲击元婴" // 该层突破所用命令

    * `success_prob`: 0.0–1.0  // 该层突破成功概率（当前等级默认从0.95递减到0.1作为默认配置）

    * `events_on_success`: \[event\_id...] // 触发的成功事件（默认是正常升级成功）

    * `events_on_fail`: \[event\_id...]    // 触发的失败事件（默认是回退一个小境界）
      }

* 若某层不需要材料与概率，`breakthrough` 可省略或留空，视为“自动突破”。你给出的【筑基丹】【结丹三宝】【元婴三宝】仅作为默认示例，我们将落在该 JSON 的默认模板中，后台可整层覆盖或个别层定制。

**系统 API（统一门面）**

* `game.can_breakthrough(user_id)`：判断当前修为是否达到“下一境界”的升级条件，返回 `{can, next_realm, blocked_by(items/prob/command), reason}`。

* `game.auto_breakthrough_scan_once()`：一次扫描处理（仅内部使用于事件效果）：

  * 遍历达标用户 → 能自动突破则直接提升并写入“成功提示通知”；

  * 需材料/命令/概率的层 → 写入“天劫阻断提示通知”（引导使用命令）。

* `player.check_and_update_realm` 保留，且扩展：当 `can_breakthrough` 表示该层需渡劫流程时，不进行自动提升，只生成阻断状态/提示。

**事件系统统一调度**

* 仅保留一个全局轮询（`PluginService._start_cron_scheduler`），将 `cron_poll_interval_seconds` 下调为 1 秒（或保持原配置，推荐 1 秒以便细颗粒度）。

* 为“自动突破扫描”创建一条事件：

  * `trigger_type`: `cron`（无需具体 cron 表达式，检查器每秒触发，靠事件自身 `cooldown` 控制独立间隔）

  * `cooldown`: 2 // 表示这条事件每 2 秒执行一次

  * `effects`: 使用 `generic_api` 调用 `game.auto_breakthrough_scan_once`（效果返回为空，由 API 内部写入 `notification`）。

* 以后新增“不同间隔不同判断”的定时检测，均增添新的事件，给各自设置 `cooldown` 即可，统一由这一个轮询驱动。

**命令与流程**

* `main.py` 仅注册：`开始筑基`、`冲击结丹`、`冲击元婴`。

* `player_handlers.py` 实现命令逻辑：

  * 读取当前阻断的目标境界与 `breakthrough` 配置，校验/扣材（`game.adjust_value(target='item', delta=-n)`），按 `success_prob * 灵根突破加成` 掷骰；

  * 成功：更新 `realm_name`，写入“恭喜 @{道号} … 成功突破至【等级】！”通知；可触发 `events_on_success`；

  * 失败：写入失败提示；

**提示投递（统一输出）**

* 所有后台检测/命令结果通过 `user_buffs` 写入 `buff_type='notification'`，`buff_name='breakthrough_notice'` 或失败/阻断对应名称，文案遵循修真语境与重点符号；

* `PluginService.handle_message` 在策略 gating 后统一弹出并清除通知（沿用“深度闭关结算”的风格），无需额外推送能力。

**示例文案**

* 成功：`恭喜 @{道号} 道友,修为精进,成功突破至【{等级}】!`

* 阻断：`天道感应,{等级}之劫已至! @{道号}的修为已达【{等级}】! 前路已被【{等级}天劫】所阻断. 你必须集齐{所需的道具}至宝,方可使用【{command}】命令,渡劫。`

* 失败：按 `events_on_fail` 配置补充。

**变更范围与约束**

* 不改动原功能的大逻辑；所有新增基于现有模块、遵循相对导入与 PEP8；

* 数值变更统一走 `game.adjust_value`；SQLite WAL 与外部注释 SQL 保持现状；

* 前台/后台共享同一套 API；所有文本无硬编码，均由 `realm_tiers` 与事件配置驱动。

**验证步骤**

1. 后台写入全境界 `realm_tiers` 配置（含材料/概率/命令）；
2. 将 `cron_poll_interval_seconds` 设为 1，创建“自动突破扫描”事件并设 `cooldown=2`；
3. 提升测试玩家修为至达标：2 秒内若可自动突破则生成成功通知；若需渡劫则生成阻断提醒；
4. 准备材料执行 `渡劫/冲击结丹/冲击元婴`，验证成功/失败与 `realm_name` 变更；
