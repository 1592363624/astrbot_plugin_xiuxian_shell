## 变更准则

* 楼层改为“手动配置”，初始化默认 10 层，可继续新增/批量生成；5×=精英、10×=首领为系统内置规则，初始化时自动标注，之后可手动覆盖

* 删除旧“奖励模板/奖励项”体系；奖励来源统一为“难度默认奖励 + 概率池 + 首通加成 + 楼层叠加(可选)”

* 玩家属性统一为“战力 power”；移除 `xp/hp` 物理列，并在统一入口做兼容映射（老代码如有 `xp` 变更，自动作用到 `power`）

## 删除与迁移

* 删表：`tower_reward_profiles`、`tower_rewards`

* 删字段：`tower_floors.reward_profile_id`

* 删代码与前端：移除与上述两表相关的全部 API/页面/调用（包括 `tower.py` 中基于 `reward_profile_id` 的发奖）

* 玩家表迁移：

  * 删除 `players.xp` 与 `players.hp`

  * 新增 `players.power INTEGER NOT NULL DEFAULT 0`

  * 兼容：`adjust_value('xp', ...)` 映射为 `adjust_value('power', ...)`，以避免未迁移模块报错；并提供只读视图 `v_players_xp` 返回 `power` 以兼容查询

## 固定规则（不入配置）

* 楼层类型：`floor % 10 == 0 → boss`；`floor % 5 == 0 → elite`；否则 `normal`（初始化时自动标注，后台可手动改）

* 首杀公告：首领层首次被全服击破必公告

* 默认奖励引擎：始终启用；如有楼层叠加则追加

* 表达式安全函数：内置 `min,max,floor,ceil,pow`

## 战力/难度校准（基于你提供的境界数据）

* 数据源：你提供的境界序列（含 `standard_xp` 与 `prev_peak_xp`）

* 玩家所在境界索引 `r` 与段内进度：

  * `segment_need = standard_xp[r] - prev_peak_xp[r]`

  * `progress = clamp((power - prev_peak_xp[r]) / segment_need, 0, 1)`（注意此处用 `power`，初始等于原 `xp`）

* 默认玩家战力函数（仅依赖 `power` 与境界）：

  * `user_power = realm_step[r] * (0.5 + 0.5 * progress)`

  * `realm_step[r]` 由境界段 XP 的增长趋势生成的严格递增序列，用于保证“每境界≈10层”的校准

* 楼层战力曲线：

  * 普通：`floor_power = base * growth^(floor-1)`；求解 `base/growth` 使 `floor_power(10*r) ≈ median(user_power at realm r)`

  * 精英：× `1.25`；首领：× `1.6`（可随难度再乘以系数）

## 奖励计算（RewardEngine）

* 输入：`user_id, floor, difficulty(easy|normal|hard), is_first_clear, type(normal|elite|boss)`

* 流程：

  1. 取难度默认奖励，算 `base + per_floor * floor`
  2. 乘类型系数（精英/首领）
  3. 加随机区间（power/gold），按 `expr_mode` 处理表达式（若配置）
  4. 概率池抽取：按难度池、支持 `only_first_clear`
  5. 首通加成：叠加精英/首领的首通数值与稀有条目（如配置）
  6. 楼层叠加（如有）

* 输出：`{power_delta, gold_delta, items:[{item_id,count}]}` + `debug`
