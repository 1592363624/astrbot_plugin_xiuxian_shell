# 必须遵循的规则
每次添加的新功能模块禁止出现硬编码,配置项要尽量考虑到兼容性和可扩展性,不能只考虑眼前的内容,游戏相关的各项数据都需要有相关的查询和编辑接口,在后台管理有相应入口并且都可以在后台管理自定义更改
插件的数据存储目录:"E:\AstrBot\data\plugin_data\{插件名}\{插件名}.db"
每次数据库的字段内容发生变化,都需要创建相关的数据库迁移脚本,并在插件启动时自动应用迁移
我希望main.py里面只能是注册命令,不要有逻辑处理搞得代码太长了,逻辑处理请放在其他模块
不使用 requests，使用 aiohttp 或 httpx
严格遵循PEP8规范，擅长将任务拆解为最小单元，采用分步式开发方法。  
最重要的:必须避免语法警告与未定义引用和模块未定义等错误，代码必须可编译。  
增删改了功能记得同步更新相关数据库代码、后台管理服务功能代码,前端用户查询界面,readme等等
不是必要的情况下不允许在添加新功能时更改原有的功能的代码
可以操作的模块描述提示后面加上指令操作的示例(为了保持简洁,如果都是一样的不要全部都加),功能和变量后面尽量加上相关的备注
使用SQLite（开启 WAL 模式）并且配置External Comments SQL
在计划停机或释放文件占用前，建议执行 wal_checkpoint(TRUNCATE) 。
不要有重复代码,尽量提取方法并确保代码整洁,确保方法的通用性
不允许存在实际上不存在你自己编造幻想的API和方法，代码满足Python 版本 3.10
前台和后台尽量共享同一套API接口，提高代码复用性和维护性
如果需要运行项目告诉我怎么验证你的结果就行了,让我来运行项目,因为需要特殊的方法,你是运行不起来的
所有的数值的增加和减少尽量用同一个接口,正数表示增加,负数表示减少
保持所有访问该库的进程使用一致的 WAL 模式，避免被其他进程改为 DELETE 模式导致行为不一致。
